## 생성 방법

적용 범위는 **0단계의 난이도 0·1·2**다. 기존 단계 1~5의 수순·메이트·엔드게임 목표는 유지한다. 메이트 문제의 기물을 임의로 옮기면 풀이가 사라질 수 있으므로 이번 생성기를 적용하지 않는다. 전 단계에 이미 적용된 균형 추출, 좌우 변형, 추가 검증, 성공률 기반 승급은 계속 사용한다.

1. 기존 방식으로 난이도와 기물 종류가 균형 잡힌 학습 PGN 배치를 선택한다. 이전 난이도 복습 및 양쪽 색 교대도 유지한다.
2. 기본 확률 50%로 새로운 배치 생성을 시도한다.
3. 해당 종류의 아군 포획 기물 하나를 원래 비어 있던 칸으로 반드시 옮긴다. 추가로 다른 기물 0~2개를 빈칸으로 옮길 수 있다. 기물의 종류·개수·색은 유지한다.
4. 양쪽 킹이 체크받는 배치, 잘못된 폰 위치, 종료된 배치, 제외 목록에 있는 배치를 거부한다.
5. **옮긴 기물이 새로운 출발 칸에서** 기존 난이도 조건을 만족하는 포획을 할 수 있어야 채택한다. 다른 기물의 기존 정답만 남은 배치는 채택하지 않는다.
6. 최대 12번 안에 실패하면 원래 PGN 배치로 진행한다. 따라서 실제 생성 비율은 50%보다 낮을 수 있다.

난이도 정의는 기존 수집기의 기준과 같다.

| 난이도 | 유지 조건 |
|---|---|
| 0 | 총 4~6개 기물, 유리하고 즉시 되잡히지 않는 비종료 포획 |
| 1 | 총 7~12개 기물, 유리하고 즉시 되잡히지 않는 비종료 포획 |
| 2 | 총 4~20개 기물, 되잡혀도 순이득인 비종료 포획, 더 쉬운 안전한 유리한 포획은 없음 |

유리함은 기존 보상 판정과 동일하게 `즉시 얻는 점수 - 상대의 가장 큰 1수 물질 이득 > 0`이며, 상대에게 즉시 체크메이트도 허용하지 않는다. 더 깊은 엔진 최선 수 판정은 아니다.

생성 문제는 실제 경기에서 나온 수순이라고 주장하지 않는 **합성 전술 배치**다. 과거 수순은 유효하지 않으므로 캐슬링·앙파상·반복 이력·반수 카운터를 초기화한다. 실제 PGN 에피소드는 기존 이력을 그대로 사용한다. 포획 단계의 종료 조건은 여전히 1 ply이고, 보상과 Action Masking도 그대로다. 동일 생성 배치가 미래에 다시 나올 수 있으며 무한 고유 배치를 보장하지 않는다.

## 검증 데이터 분리

`Tools/BuildCaptureExclusions.py`가 고정 학습·평가·추가 검증 및 Legacy 검증 배치의 SHA-256 식별자 17,086개를 만든다. 색 교환/랭크 반전과 좌우 반전은 같은 배치로 취급하며, 권리·카운터가 달라도 같은 기물 배치와 차례이면 제외한다.

- 고정 학습 배치도 제외하므로 생성기가 기존 목록의 다른 배치를 그대로 재사용하지 않는다.
- Unity에 추가되는 자료는 제외용 해시다. 검증 정답·검증 수순은 학습기에 제공하지 않는다.
- 새로운 PGN 데이터를 만들 때 `python Tools/BuildCurriculumDataset.py`가 제외 목록도 갱신한다. `PrepareGeneralizationDataset.py`를 직접 실행했다면 `python Tools/BuildCaptureExclusions.py`도 실행해야 한다.
- 현재 데이터 ID와 제외 리소스의 ID가 다르면 오류를 내어 오래된 제외 목록으로 학습하지 않게 한다.
- 고정 평가가 승급과 튜닝에 쓰이므로 여전히 validation이며, 최종 blind test라고 부르면 안 된다.

## 설정과 실행

Training 환경 Inspector:

| 설정 | 기본값 | 의미 |
|---|---:|---|
| Capture Generation Probability | 0.5 | 생성 시도 비율 |
| Capture Generation Attempts | 12 | 에피소드당 최대 후보 수, 1~64 |

`config/chess_sac.yaml`의 `environment_parameters.capture_generation_probability: 0.5`가 Inspector 확률보다 우선한다. 0이면 생성을 끈 비교 실험을 할 수 있다. 관측 844개, 행동 8577개, `ChessV1` 네트워크 형식은 유지했다.

이번에는 Unity 실행 파일 재빌드가 필요하다. 진행 중인 기존 학습은 자동 중단하거나 변경하지 않았다. 기존 실행을 정상 종료한 후 Unity의 `ChessBot > Training > Build Windows Training Player`로 현재 씬을 빌드한다.

```powershell
python Tools/TrainChessSuccess.py config/chess_sac.yaml --run-id=curriculum_5 --initialize-from=curriculum_4 --env=output/chess-training/ChessTraining.exe --no-graphics --time-scale=30 --num-envs=12 --torch-device=cuda
```

이미 사용한 run-id라면 새 이름을 선택한다. `--initialize-from`으로 가중치를 가져오고 새 학습 분포·평가 기록을 시작한다. 이전 run의 `--resume`은 새 분포와 섞이지 않도록 fingerprint 검사가 거부한다. 새 run을 중단했다가 이어갈 때는 `--initialize-from` 대신 `--resume`을 사용한다. 일반 `mlagents-learn`만 실행하면 성공률 기반 승급은 실행되지 않는다.

후속 요청으로 승급 성공률 기준을 10%포인트씩 낮췄다. 난이도 0은 두 검증 모두 80%를 연속 2회 통과해야 한다. 생성 문제 성공률만으로 승급하지 않는다. `TrainingSuccess`가 1이고 `GeneratedCapture/Success`가 낮다면 고정 배치와 새 좌표 배치의 격차가 아직 남은 것이다.

게임 기록에는 `generatedPosition`, `generatorVersion`, `generatorBaseFen`을 추가했다. 생성 문제의 `historyInitialFen`은 실제 생성 FEN이고 `historyMoves`는 빈 배열이다. `sourceGame`, `sourceStartPly`, `sourceHorizontal`, `sourceMirrored`, `historyOffset`은 변형의 바탕이 된 PGN의 출처 정보이며, 생성 FEN으로 이어지는 실제 경기 수순을 뜻하지 않는다.

## 승급 기준 조정 (2026-10-02)

| 승급 대상 | 기존 | 변경 |
|---|---:|---:|
| 포획 난이도 0 | 90% | 80% |
| 포획 난이도 1·2 | 85% | 75% |
| 1단계 교환·방어 | 70% | 60% |
| 2단계 메이트 | 85% | 75% |
| 3단계 엔드게임 | 70% | 60% |
| 4단계 중반 | 55% | 45% |

5단계는 마지막 단계로 추가 승급이 없다. YAML의 `promotion_thresholds[0]`은 사용하지 않는 예약 값이므로 그대로 두었다. 기존/추가 검증 및 해당 단계의 유형별 승급 검사에 동일한 새 기준이 적용된다. 이전 단계 유지 기준, 평가 표본 수, 최소 단계 학습 100,000 step, 평가 간격 50,000 step, 연속 2회 통과 조건은 유지한다.

이번 임계값 변경만으로 Unity를 재빌드할 필요는 없다. 실행 중인 Python 학습기는 시작할 때 설정을 읽으므로 재시작해야 적용된다. 현재 재개 검사는 평가 설정 전체를 비교하므로 변경 전 설정으로 시작한 run에는 `--resume`이 거부된다. 해당 run을 `--initialize-from`으로 지정하고 새 run-id로 시작한다. 새 기준으로 이미 시작한 run은 같은 설정으로 `--resume`할 수 있다.
