## 2. 공통 코드 규칙

- 각 스크립트는 SOLID 원칙을 준수하며, 주요 변수와 핵심 로직에 주석을 포함한다. 특히 좌표계, 특수 수, 턴 전환, 보상 및 초기화 순서의 의도를 설명한다.
- 체스 진행 관련 코드는 `Assets/Scripts/Chess/`에 둔다. 기존 문서의 `Scripts/Chess`는 Assets 기준 경로로 해석한다.
- 규칙·상태 모델은 Unity에 의존하지 않는 C#으로 작성한다. `MonoBehaviour`, 화면 좌표, GameObject, Agent, 보상 값에 의존하지 않는다.
- 보드 상태의 변경은 대국 제어기를 통한다. UI와 Agent에 내부 배열을 직접 수정할 권한을 주지 않는다.
- 수 검증과 결과 판정은 한 구현을 공유한다. 사람 입력, 학습, 추론에 별도 규칙을 복제하지 않는다.
- 클래스·공개 멤버는 PascalCase, 매개변수·지역 변수는 camelCase, 비공개 필드는 `_camelCase`를 사용한다. Unity 참조는 `[SerializeField] private`로 노출하고 초기화 시 필수 참조를 검증한다.
- 파일명은 주 타입명과 맞춘다. 네임스페이스는 `ChessBot.Chess.*`, `ChessBot.Agents` 등 책임과 경로를 따른다. 이는 기존 코드에서 추출한 관례가 아닌 신규 구현 기준이다.
- 인터페이스는 플레이어, 보상 정책, 기록 저장소처럼 교체가 필요한 경계에 둔다. 전역 싱글턴 대신 씬 초기화 지점에서 의존성을 연결한다.
- 설정 자산은 읽기 전용 구성으로 취급한다. 대국별 상태를 공유 ScriptableObject나 static 필드에 저장하지 않는다.

## 3. 폴더와 의존성

다음은 목표 구조다. 실제 기능을 구현할 때 필요한 파일과 어셈블리를 추가한다.

```text
Assets/
  Scripts/
    Chess/
      Core/           좌표, 기물, 수, 보드 상태, 규칙과 결과 판정
      Application/    대국 제어, 플레이어 계약, 턴 진행과 기록 데이터
      Presentation/   보드 표시, 사람 입력, 승격 선택과 결과 UI
    Agents/           ChessAgent, 관측·행동 변환, 보상 계산
    Training/         학습 대국 초기화, Curriculum 적용, 평가·기록 저장
    Bootstrap/        씬 참조 연결, 대전 모드 구성
  Tests/
    EditMode/         규칙, 상태 전이, 행동 변환 단위 검증
    PlayMode/         턴 진행, 사람 입력, Agent 에피소드 통합 검증
  Scenes/             현재 SampleScene, 향후 대국·학습 씬
  Settings/           기존 렌더링 설정과 향후 대국·학습 설정 자산
config/
  chess_sac.yaml      향후 SAC / Self-Play / Curriculum 설정
Codex/
  001.Architecture.md 이 문서
```

의존 방향은 아래처럼 유지한다. 화살표는 “참조한다”를 뜻한다.

```text
Presentation ──> Application ──> Core
Agents ────────> Application, Core, ML-Agents
Training ──────> Agents, Application
Bootstrap ────> Presentation, Training, Agents, Application
```

`ChessBot.Chess.Core`는 Unity 참조를 차단한 asmdef로 분리하고, 나머지도 위 경계를 기준으로 나눈다. 테스트는 대상 어셈블리를 참조하고 런타임은 테스트를 참조하지 않는다. Editor 전용 코드가 필요하면 별도 Editor 어셈블리에 둔다.

## 4. Chess: 상태와 규칙

### 4.1. 주요 타입

| 타입 | 책임 |
| --- | --- |
| `Square`, `PieceColor`, `PieceType`, `Piece` | 좌표, 진영, 종류를 표현하는 값 타입 |
| `Move` | 출발·도착 칸과 승격 종류. 캐슬링·앙파상 여부는 규칙 엔진에서 검증 |
| `BoardState` | 64칸 기물 배치, 현재 진영, 캐슬링 권리, 앙파상 후보 칸, 반수 카운터와 전체 수 번호 |
| `PositionHistory` | 초기 포지션을 포함한 반복 판정 이력. 대국별로 소유 |
| `MoveGenerator` | 후보 수 생성과 킹 안전성 검사에 따른 합법 수 생성 |
| `ChessRules` | 수 적용, 공격 칸 검사, 체크, 특수 규칙 및 무승부 선언 가능 여부 |
| `GameResultEvaluator` | 체크메이트·자동 무승부 판정과 종료 사유 생성 |
| `MoveResult`, `GameResult` | 실제 포획 기물·칸, 변경된 칸, 결과 및 종료 사유 등 불변 결과 데이터 |

보드 좌표는 백 기준으로 `a1 = (0, 0)`, `h8 = (7, 7)`, 배열 인덱스는 `rank * 8 + file`로 통일한다. 백 폰은 rank 증가 방향, 흑 폰은 감소 방향으로 이동한다. 화면 회전은 표시·입력 변환에서 처리한다.

합법 수 생성은 원본을 변경하지 않는 복사본 또는 정확히 복구 가능한 임시 상태를 사용한다. 임시 수 적용으로 실제 반복 이력, 보상, 이벤트를 갱신하지 않는다.

### 4.2. 수 적용 계약

- 초기 배치에서는 백부터 시작한다. 한 진영이 둔 한 수를 1 ply(반수)로 센다.
- 후보 수를 만든 뒤 적용 결과에서 자신의 킹이 공격받는 수를 제거한다. 킹을 포획하는 수는 생성하지 않고 체크메이트로 승패를 결정한다.
- 공격 칸 검사는 합법 수 생성과 분리해 재귀 의존을 피한다. 폰의 공격 방향과 고정된 기물의 공격 칸도 구분해 처리한다.
- 캐슬링은 킹·룩 이동을 하나의 수로 적용한다. 권리, 사이 칸, 킹의 시작·통과·도착 칸 안전성을 검사한다. 킹·해당 룩 이동 및 원래 칸의 룩 포획 시 권리를 갱신하며 복귀·승격으로 복원하지 않는다.
- 앙파상은 직전 두 칸 전진 직후에만 가능하다. 잡히는 폰의 실제 칸을 비운 상태에서 킹 안전성을 검사한다.
- 승격은 퀸·룩·비숍·나이트를 각각 별도 수로 취급하고 선택까지 완료되어야 턴을 넘긴다.
- 수 적용은 기물 변경, 특수 권리, 카운터, 다음 진영, 반복 이력을 일관되게 갱신한다. 포획 또는 폰 이동이면 반수 카운터를 0으로 만든다.
- 잘못된 수는 실패 사유를 반환하고 상태·턴·기록·보상을 변경하지 않는다.

### 4.3. 종료와 무승부

표준 규칙의 판정 근거는 [FIDE Laws of Chess](https://handbook.fide.com/chapter/e012023)의 5조와 9조를 따른다.

| 조건 | 처리 |
| --- | --- |
| 체크 중이고 합법 수 없음 | 체크메이트, 상대 승리 |
| 체크가 아니고 합법 수 없음 | 스테일메이트, 자동 무승부 |
| 어느 쪽도 어떠한 합법 수순으로도 체크메이트 불가능 | Dead position, 자동 무승부 |
| 동일 포지션 3회 / 포획·폰 이동 없이 각자 50수 | 현재 차례의 플레이어가 선언할 수 있는 무승부 |
| 동일 포지션 5회 / 포획·폰 이동 없이 각자 75수 | 자동 무승부. 마지막 수가 체크메이트이면 체크메이트 우선 |

50수·75수는 각각 100·150 ply로 검사한다. 반복 키에는 배치, 차례, 캐슬링 권리, 합법적인 앙파상 가능성을 포함하고 수 번호는 제외한다. 해시를 사용할 경우 충돌로 동일 포지션을 오판하지 않도록 한다.

`ClaimDraw`는 일반 수와 별도 명령이다. 현재 포지션뿐 아니라 제출한 합법 수로 선언 조건을 충족할 예정인 경우도 검사한다. 유효한 선언은 대국을 종료하고, 무효 선언은 상태를 유지한다. 사람과 Agent 모두 선언 여부를 선택할 수 있어야 하며 3회·50수 조건을 자동 종료로 바꾸지 않는다.

Dead position은 기물 점수 합이나 대표적인 기물 부족 사례만으로 완전히 판정할 수 없다. 대표 사례와 봉쇄 포지션을 포함한 판정 방법·검증 자료를 확보해야 하며, 일부 사례만 처리한 상태를 표준 규칙 완료로 간주하지 않는다.

README에 없는 체스 시계, 대면 경기의 터치무브·심판 벌칙, 합의 무승부 UI는 별도 범위 결정이 필요하다.

## 5. 대국 제어와 표시

`ChessGameController`는 대국마다 하나씩 존재하며 보드, 이력, 백·흑 플레이어, 대국 식별자와 턴 버전을 소유한다. `IChessPlayer` 경계를 통해 사람과 Agent의 수 제출을 받는다.

상태 흐름은 `Initializing → AwaitingMove → ApplyingMove → AwaitingMove 또는 Finished → Resetting`이다.

1. 초기 상태를 생성하고 결과를 먼저 검사한다. 이미 종료된 Curriculum 포지션에 행동을 요청하지 않는다.
2. 현재 진영에 읽기 전용 상태와 합법 수를 제공한다. Agent라면 이때만 결정을 요청한다.
3. 제출자의 진영, 대국 식별자·턴 버전, 현재 상태와 합법성을 다시 검사한다.
4. 유효한 명령을 한 번 적용하고 결과를 확정한다. 수 이벤트에는 보상과 표시 갱신에 필요한 실제 변경 정보를 넣는다.
5. 진행 중이면 다음 진영에 입력을 요청한다. 종료이면 추가 입력을 차단하고 결과 기록과 에피소드 종료를 한 번만 실행한다.

`BoardView`는 상태를 표시하고, `HumanMoveInput`은 화면 입력을 보드 좌표와 승격 선택으로 변환한다. 하이라이트도 공통 합법 수를 사용한다. 애니메이션이 규칙의 완료 여부를 결정하지 않으며 화면 없는 학습에서도 같은 진행 흐름을 사용한다.

대전 모드는 초기화 지점에서 구성한다.

- **Agent vs Agent:** 두 `ChessAgent`를 백·흑에 배정한다.
- **사람 vs Agent:** 사람 입력과 추론 Agent를 배정한다.
- **평가:** 학습 갱신을 끄고 고정된 상대·모델·설정으로 진행한다.

장면 전환이나 모드 변경 시 입력 대기와 이벤트 구독을 해제한다. 이전 턴의 지연 응답이 다음 대국에 적용되지 않도록 식별자와 버전을 검증한다.

## 6. Agent와 학습 경계

### 6.1. ChessAgent 기본 구현

`Assets/Scripts/Agents/ChessAgent.cs`는 ML-Agents의 `Unity.MLAgents.Agent`를 상속하고 아래 함수를 구현한다. 함수 시그니처는 현재 패키지의 `Runtime/Agent.cs`를 기준으로 한다.

| 함수 | 책임 |
| --- | --- |
| `Initialize()` | 대국 제어기, 진영, 관측·행동 변환기와 보상 정책 참조 검증 |
| `OnEpisodeBegin()` | Agent의 임시 상태를 비우고 준비 상태 통지. 공유 보드를 직접 초기화하지 않음 |
| `CollectObservations(VectorSensor sensor)` | 같은 순서·크기로 관측을 인코딩 |
| `WriteDiscreteActionMask(IDiscreteActionMask actionMask)` | 현재 상태에서 허용되는 수와 무승부 선언만 활성화 |
| `OnActionReceived(ActionBuffers actions)` | 행동을 명령으로 변환하고 제어기에 제출. 직접 말·턴을 변경하지 않음 |
| `Heuristic(in ActionBuffers actionsOut)` | 디버깅용 합법 수를 동일 인코더로 변환. 실제 사람 대전 입력은 별도 플레이어가 담당 |

매 프레임 요청 대신 현재 차례에 `RequestDecision()`을 한 번 호출한다. 자동 `DecisionRequester` 및 이전 행동 반복으로 중복 수가 발생하지 않게 구성한다. 불법 행동은 기록하고 원인을 진단하며, 조용히 임의의 합법 수로 바꾸지 않는다.

### 6.2. 관측과 행동

`ObservationEncoder`와 `ActionEncoder`를 규칙에서 분리한다. 구체적인 차원과 인덱스 배치는 학습 설계에서 결정하지만 다음 계약을 만족해야 한다.

- 관측에는 기물 종류·진영·위치, 자신의 진영, 현재 차례, 캐슬링 권리, 앙파상 가능성, 반수 카운터와 반복 관련 정보를 포함한다.
- 현재 배치의 반복 횟수 하나만으로 과거 모든 포지션의 재등장 여부를 알 수는 없다. 이력 인코딩 또는 부분 관측을 허용하는 설계를 명시하고 무승부 선언 가능 정보도 제공한다.
- 행동은 고정된 의미를 갖는 이산 인덱스와 명령 간 변환을 제공한다. 모든 합법 수, 네 종류 승격, 현재·예정 수에 의한 무승부 선언을 표현해야 한다.
- 출발·도착을 독립 분기로 나누면 조합의 합법성을 개별 마스크만으로 보장할 수 없다. 완성된 수 단위 인덱스 등 조합을 정확히 제한할 표현을 선택한다.
- 진영 상대 좌표를 사용하면 관측, 행동, 마스크에 동일 변환과 역변환을 적용한다.
- 종료 여부를 행동 요청 전에 판정해 모든 행동이 마스킹된 상태에서 결정을 요청하지 않는다.
- 관측·행동 스키마에 버전을 부여하고 모델 메타데이터에 저장한다. 크기뿐 아니라 의미가 달라진 모델도 로딩 시 거부한다.

### 6.3. 보상과 에피소드

`RewardPolicy`는 수 결과와 대국 결과를 받아 양측 보상을 계산한다. 기물 점수, 포획·피포획 점수 차의 집계 범위와 계산식, 승·패·무 보상은 학습 설정에서 정한다. 규칙 엔진에는 보상을 넣지 않는다.

포획 이벤트는 실제 제거된 기물을 기준으로 하며 앙파상도 포함한다. 교환 점수 차는 개별 포획·누적 점수 중 어떤 정의를 사용하는지 학습 설계에 명시한다. 턴 소유자에게만 보상을 전달해 상대의 피포획 보상을 누락하지 않는다. 수 보상과 종료 보상은 각각 한 번만 반영한다.

한 대국은 하나의 에피소드다. 제어기 또는 `TrainingEnvironment` 한 곳에서 다음 순서를 조정한다.

1. 입력을 차단하고 최종 결과 및 양측 종료 보상을 반영한다.
2. 초기화 전에 대국 기록을 확정한다.
3. 두 Agent 모두 `EndEpisode()`를 호출한다. 개별 콜백에서 새 대국을 시작하지 않는다.
4. 양측 준비가 끝나면 보드·차례·특수 권리·카운터·이력·Agent 임시 상태를 한 번 초기화한다.
5. 새 대국 식별자를 발급하고 첫 진영의 결정을 요청한다.

독립적인 `MaxStep`으로 한쪽만 먼저 초기화되지 않도록 Agent의 제한은 끄고 대국 단위로 관리한다. 학습 예산용 수 제한은 체스의 75수 규칙과 구분하며, 중단된 에피소드는 정상 무승부와 별도 기록한다. 중단 종료에는 패키지의 interruption API를 사용해 양측을 함께 처리한다.

### 6.4. SAC, Self-Play와 Curriculum

README의 SAC 선택을 유지한다. 공식 문서는 SAC의 이산 행동 및 Self-Play를 설명하지만, Unity 4.1.0에 맞는 Python 패키지 조합과 실행 성공은 별도 검증해야 한다. 참고: [Trainer 문서](https://unity-technologies.github.io/ml-agents/Python-On-Off-Policy-Trainer-Documentation/), [학습 설정 문서](https://unity-technologies.github.io/ml-agents/Training-Configuration-File/).

- `config/chess_sac.yaml`에 Behavior 이름, SAC 설정, Self-Play 상대 교체·저장 설정, Curriculum 환경 파라미터와 학습 예산을 작성한다. 현재 파일이 비어 있으므로 실행 가능한 설정으로 간주하지 않는다.
- 대칭 정책을 공유하는 양측은 같은 Behavior 이름과 서로 다른 Team ID를 사용한다. 대국의 백·흑 역할과 팀/정책 배정을 명시적으로 관리한다.
- Curriculum은 초기 포지션·보상 설정·과제 난도를 에피소드 경계에서 변경한다. 1단계는 합법적인 턴제 대국 수행이며 이후 단계와 전환 지표는 미정이다.
- 합법 수 마스크가 규칙을 강제하므로 불법 수가 없다는 사실만으로 전략을 학습했다고 평가하지 않는다.
- Python 버전, `mlagents`·`mlagents-envs`와 관련 패키지 버전, 시드, 설정 사본, 관측·행동 스키마, 체크포인트 및 추론 모델을 실행 식별자별로 기록한다.

## 7. 저장과 평가

`GameRecord`에는 초기 포지션, 수 목록과 승격·선언, 결과·종료 사유, ply 수, 백·흑 배정, 시드, 모델과 상대 정책 식별자를 남긴다. 저장 실패가 규칙 상태를 되돌리거나 결과 이벤트를 중복 발생시키지 않도록 저장소를 분리한다.

평가는 고정한 모델을 불러오고 백·흑 배정을 균형 있게 구성한다. 상대 정책, 대국 수, 승·무·패, 중단 수, 사용 모델, 설정 및 실행 버전을 함께 기록한다. 평가 상대·대국 수·목표 성능은 학습 설계 단계에서 확정한다.

추론 모델은 시작 시 스키마와 설정 호환성을 검사하고 오류를 표시한다. 모델 부재를 임의 행동으로 대체해 정상 평가 결과처럼 기록하지 않는다.

## 8. 구현 순서와 검증 기준

| 순서 | 구현 범위 | 완료 확인 |
| --- | --- | --- |
| 1 | 상태·좌표·초기 배치·턴 | 초기 32개 기물, 백 선행, 좌표 변환, 초기화 테스트 |
| 2 | 이동·포획·체크·특수 수 | 핀, 양쪽 캐슬링, 앙파상 노출 체크, 네 종류 승격, 킹 인접, 불법 수 상태 불변 테스트 |
| 3 | 결과·이력·선언 | 메이트와 스테일메이트 구분, 반복 권리 차이, 100/150 ply 경계, 예정 수 선언, Dead position 검증 |
| 4 | 제어기·표시·사람 입력 | 한 수 한 번 적용, 승격 대기, 지연 입력 차단, 모드별 동일 규칙 사용 |
| 5 | Agent·관측·행동·보상 | 인코딩 왕복, 합법 수와 마스크 일치, 진영 변환, 양측 보상, 동시 종료와 단일 초기화 |
| 6 | 학습·모델·평가 | 짧은 SAC Self-Play 실행, 체크포인트 저장·재개, 추론 모델 로딩, 재현 가능한 평가 기록 |

규칙과 인코더는 EditMode에서 검증하고, 씬 연결·입력·Agent 생명주기는 PlayMode에서 검증한다. 알려진 포지션의 합법 수 집합과 perft(깊이별 수순 수)를 검증 자료와 대조한다. perft만으로 무승부 선언이나 에피소드 처리를 검증했다고 간주하지 않는다.

표준 규칙 테스트와 대국 초기화 검증을 통과한 뒤 학습을 시작한다. 이번 문서 작성에서는 씬 실행·빌드·학습을 수행하지 않았다.

## 9. 후속 설계에서 확정할 항목

- 관측 이력 표현, 행동 인덱스 및 무승부 선언 인코딩의 구체적인 크기와 버전.
- 기물 점수, 교환 점수 차 계산식, 종료 보상과 포획 보상의 비중.
- Curriculum의 후속 단계, 측정 지표, 전환 기준과 학습 예산.
- Unity 패키지와 호환되는 Python 환경, 타깃 플랫폼 및 학습 실행 절차.
- 일반적인 Dead position까지 포함하는 판정 알고리즘과 검증 자료.
- 평가 상대, 대국 수와 목표 성능.
