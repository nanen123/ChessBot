# 성공률 기반 자동 평가와 커리큘럼

## 실행

프로젝트 루트에서 CUDA용 ML-Agents 1.1.0 환경을 활성화한다. 최초 한 번만 평가 의존성을 별도 폴더에 준비한다. 기존 학습 환경의 패키지는 교체하지 않는다.

```powershell
python -m pip install --no-deps --target output/training-validation/pgn-deps -r Tools/requirements-evaluation.txt
```

확대된 데이터가 플레이어에 포함되도록 Unity에서 `ChessBot > Training > Build Windows Training Player`로 다시 빌드한다. `Use Curriculum`을 켜고 `Position Source = Pgn Training`을 사용한다. 아래 명령은 **기존 mlagents-learn을 내부에서 실행하는 프로젝트 전용 실행기**다.

```powershell
python Tools/TrainChessSuccess.py config/chess_sac.yaml --run-id=success-first --env=output/chess-training/ChessTraining.exe --no-graphics --torch-device=cuda
```

기존 `--num-envs`, `--initialize-from`, `--results-dir`, `--resume` 등 학습 인자를 전달할 수 있다. `--force`는 평가 기록 보호를 위해 지원하지 않는다. 실행기는 설치된 패키지를 수정하지 않고 ML-Agents 1.1.0의 TrainerController를 확장한다. 다른 버전에서는 실행을 거부한다.

**일반 mlagents-learn 명령만 실행하면 stage 0에 머문다.** YAML의 진행률 기반 승급은 제거했고 curriculum_stage의 기본값은 0이다. 자동 평가와 승급에는 위 실행기를 사용해야 한다. 새 설정은 `config/chess_evaluation.yaml`, 다른 평가 설정은 `--evaluation-config 경로`로 지정한다.

## 데이터

총 학습 16,385개와 평가 1,025개이며 단계별 수량은 [커리큘럼 표](005.Curriculum.md)를 따른다. 동일 경기의 여러 위치가 포함될 수 있다. 선수 실력 필터나 엔진 평가로 엄선한 대규모 데이터셋은 아니다. 출처와 선정 기준은 [데이터 안내](../Data/Curriculum/README.md)를 따른다.

평가 자료는 학습 trajectory나 gradient 계산에 들어가지 않지만 **승급에 반복 사용하는 검증 세트**다. 최종 기력 주장은 별도의 미사용 테스트 세트로 확인해야 한다. 색 반전한 두 판도 완전히 독립적인 표본은 아니다.

## 평가 방식

학습 step 50,000마다 현재 모델을 저장한 뒤 학습 업데이트를 잠시 멈추고 평가한다. CPU ONNX Runtime으로 deterministic_discrete_actions를 사용하며 모델 가중치를 업데이트하지 않는다. Unity와 같은 844개 관측 및 8577개 행동 인코딩·합법 수 마스킹을 사용한다. 이전 PGN 수순을 재생해 반복 이력을 보존하고 에피소드 반수는 0부터 센다.

현재 단계와 이전 단계를 모두 평가한다. 0단계는 현재 및 이전 난이도별 64개 위치를 양색으로 평가해 각각 128개 사례를 사용한다. 1~5단계는 단계별 128개 위치를 유형별로 균형 선택하여 양색 256개 사례를 평가한다. 난수 seed와 상대 정책은 고정한다. 5단계는 표준 배치 1개와 6/8-ply 오프닝 127개에서 모델의 백/흑을 교대한다. 보드 자체는 반전하지 않는다. 유형별 결과는 categories에 기록하며 기존 단계 전체 성공률로 승급한다. evaluation_version은 4다.

| 단계 | 성공 판정 | 승급 기준 | 이전 단계 유지 기준 |
| --- | --- | --- | --- |
| 0-A 공짜 포획 | 4~6기물에서 첫 수 유리한 포획 또는 실제 승리 | 90% | 80% |
| 0-B 안전한 포획 | 7~12기물에서 첫 수 유리한 포획 또는 실제 승리 | 85% | 75% |
| 0-C 유리한 교환 | 되잡힘 가능 배치에서 첫 수 유리한 포획 또는 실제 승리 | 85% | 75% |
| 1 교환·방어 | 12반수 종료 시 순포획 점수 양수 또는 실제 승리 | 70% | 60% |
| 2 메이트 | 모델의 선택 이후 모든 합법적 방어 응수에도 최대 3반수 안에 메이트 | 85% | 75% |
| 3 엔드게임 | 100반수 안에 실제 승리 | 70% | 60% |
| 4 중반 | 256반수 안에 실제 승리 | 55% | 45% |
| 5 전체 대국 | 512반수 안에 실제 승리 | 마지막 단계, 승급 없음 | 계속 측정 |

메이트 외 단계의 상대는 **고정된 1수 기물 가치 휴리스틱**이다. 메이트 우선, 포획 이득과 즉시 되잡힘 손실을 보고 동점은 고정 seed로 선택한다. 현재 위치에서 무승부 청구 가능 시 청구한다. Stockfish나 공식 Elo가 아니며, 이 상대를 이겼다고 높은 기력을 보장하지 않는다. 메이트 단계는 이 상대 대신 모든 응수를 검사한다.

무승부와 한도 초과는 성공률에서 실패로 센다. 한도 초과를 정상 무승부로 기록하지 않는다. 단계 1의 교환은 최선의 방어를 완전히 증명하는 시험이 아니다. 결과 파일에 승/패/무승부/한도, 반수, 순포획 점수, 원본 경기와 색 반전을 남긴다. 메이트의 반수는 분기 평가이므로 단일 값 대신 null로 기록한다.

평가 반수 한도는 설정 파일의 maximum_plies를 사용한다. Inspector의 단계별 반수 한도를 바꾸면 평가 설정도 함께 맞춰야 한다. 보상 크기는 평가 성공 판정에 사용하지 않는다.

## 승급과 중단

- 현재 단계(0단계는 현재 세부 난이도)에서 최소 100,000 training step을 수행해야 한다.
- 현재 단계 성공률과 이전 단계 유지 기준을 모두 **연속 2회** 만족해야 한 단계만 승급한다.
- 실패하면 연속 통과 횟수가 0이 된다. 자동 강등은 하지 않는다.
- 평가 누락·표본 부족·불법 모델 행동·데이터 오류는 승급하지 않고 오류로 학습을 중단한다.
- 승급 시 진행 중 대국을 학습기의 환경 reset 경로로 종료한다. 이에 별도 승패 보상은 주지 않는다. 목표가 바뀐 이전 단계 SAC replay buffer도 비운 후 체크포인트를 저장한다.
- 학습 예산(max_steps)에 도달하면 기준 미달이어도 종료한다. 모든 단계까지 자동 도달하는 것은 아니다.

임계값은 초기 실험값이며 현재 데이터 난도와 학습 결과를 보고 조절해야 한다. 검증용 smoke 설정에서는 승급 연결만 시험하기 위해 임계값을 0으로 낮춘다. 이는 실력 검증 결과가 아니다.

## 결과와 재개

`results/<run-id>/evaluation/`:

- `<step>.json`: 모든 사례별 결과, 단계별 성공률, 모델·데이터 해시, 승급 여부
- `history.jsonl`: 시간순 비교용 요약
- `passed-stage-N.onnx`: 해당 단계를 통과한 모델 보관
- `passed-stage-0-capture-D.onnx`: 포획 세부 난이도 D를 통과한 모델

`results/<run-id>/success_curriculum.json`: 현재 단계, 단계 시작 step, 마지막 평가 step, 연속 통과 횟수와 설정·데이터 지문. TensorBoard에는 Evaluation/LessonN/Success와 Evaluation/Stage를 기록한다. 상수 환경 파라미터를 사용하므로 기본 Environment/Lesson Number 표시는 0이며, 실제 단계는 Evaluation/Stage 또는 Unity의 Curriculum/Stage로 확인한다.

```powershell
python Tools/TrainChessSuccess.py config/chess_sac.yaml --run-id=success-first --env=output/chess-training/ChessTraining.exe --no-graphics --torch-device=cuda --resume
```

같은 평가 데이터·설정으로 재개한다. 상태 파일이 없거나 지문이 다르거나 체크포인트가 상태보다 오래되면 오류로 중단한다. 이전 진행률 기반 run에는 이 상태가 없으므로 새 run ID와 `--initialize-from 기존run`으로 시작한다. 초기화 실험은 0단계부터 다시 평가한다.

## 반복 및 포획 진단 (평가 버전 2)

각 case의 metrics, 단계별 합계 metrics, TensorBoard의 Evaluation/LessonN/지표에 기록한다. 포획 기회 누락은 학습 보상이 아닌 관찰용 지표이며 승급 조건은 기존 성공률을 유지한다.

| 지표 | 의미 |
| --- | --- |
| favorable_capture_opportunities | 모델 차례에 상대의 모든 한 수 응수 후 순기물 이득이 양수인 포획이 하나 이상 있었던 횟수. 상대 메이트 인 1을 허용하는 포획 제외 |
| missed_favorable_captures / missed_favorable_capture_rate | 위 기회에서 해당 포획도 즉시 체크메이트도 선택하지 않은 횟수 / 기회 수. 기회가 없으면 비율 null |
| free_piece_losses / free_material_lost | 실제 상대 포획 후 포획한 말을 즉시 합법적으로 되잡을 수 없었던 횟수 / 잃은 점수 |
| repeated_positions / model_repetitions | 에피소드 내 동일 포지션 재방문 전체 횟수 / 모델의 수로 발생한 횟수 |
| repetitions_per_episode | 총 재방문 횟수 / 평가 에피소드 수 |
| advantageous_repetition_draws | 모델의 기물 점수 우위(>0)에서 3회 반복 청구 또는 자동 5회 반복으로 끝난 횟수. 예정 수 청구도 포함 |

포획 누락은 나쁜 수의 확정 판정이 아니다. 더 좋은 조용한 수나 장기 희생을 짧은 탐색이 놓칠 수 있다. 기물 손실도 전술적 보상이 있는 희생을 포함할 수 있고, 기물 점수 우위가 승세를 증명하지는 않는다. 메이트 2단계는 여러 방어 분기를 검증하므로 metric_scope=searched_model_decisions이고 실제 단일 대국 반복·손실 지표는 0이다. 다른 단계는 played_episode다.

반복 벌점 효과를 비교하려면 동일 데이터·seed·학습 예산으로 Inspector Repetition Penalty를 0과 0.005로 각각 빌드해 다른 run-id로 학습한다. 성공률을 유지하면서 반복 지표가 감소하는지 확인한다. 짧은 실행 검증만으로 기력 개선을 판정하지 않는다. 변경된 평가 설정과 PGN은 이전 상태 --resume 대신 새 run-id가 필요하다.

## 세부 난이도와 과적합 관찰 (평가 버전 3)

`config/chess_evaluation.yaml`의 capture_samples_per_difficulty=64와 capture_minimum_episodes=128이 포획 평가 표본 수를 결정한다. capture_training_samples=64는 각 난이도의 훈련 데이터에서 고정 seed로 고른 64개를 양색으로 별도 평가하는 값이다. 훈련 표본 성공률은 진단용이며 **승급 조건에는 사용하지 않는다**.

- Evaluation/Capture0, Capture1, Capture2 각각의 Success: 해당 난이도의 별도 평가 성공률.
- TrainingSuccess: 훈련 표본의 결정적 평가 성공률. 전체 1,024개 전수 성공률은 아니다.
- GeneralizationGap: TrainingSuccess - Success. 큰 양수이면 과적합 여부를 살펴본다.
- Evaluation/Lesson0/Success: 현재 평가한 가장 높은 포획 난이도의 성공률.
- Evaluation/CaptureDifficulty: 목표 포획 난이도. 0단계 이후에는 마지막 완료 값 2를 유지한다.

상태 파일 version=2에 capture_difficulty를 저장한다. 0-A→0-B→0-C→기존 1단계 순서다. 이전 난이도 유지 조건은 각 난이도별로 검사하므로 높은 평균 점수가 특정 난이도 실패를 숨기지 못한다. 새 난이도마다 최소 학습량·연속 통과 횟수가 새로 시작된다. 각 난이도 안에서만 같은 지표의 추이를 비교한다.

capture_promotion_thresholds / capture_retention_thresholds가 0단계의 임계값이다. 기존 promotion_thresholds / retention_thresholds의 0번 원소는 자리 유지용이며 1~4번만 일반 단계에 적용한다. YAML에는 curriculum_stage: 0과 capture_difficulty: 0 두 상수 환경 파라미터가 필요하다. 일반 mlagents-learn으로는 0-A에 머문다.

기존 결과에 새 평가 기준을 소급 적용하지 않는다. 이전 16개 포획 평가 기보는 Data/Curriculum/Legacy에 보존되어 있고 새 훈련 위치·경기와 분리했다. 새 평가 성공률은 과거 32회 평가 점수와 표본 구성이 다르다. 새 실행 예:
