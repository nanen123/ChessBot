# 전 단계 일반화 보완

0-A 진단에서 확인한 좌표 의존과 큰 일반화 격차에 대응하는 변경이다. 과적합을 완전히 방지하거나 기력 향상을 보장하지는 않는다. 보상·에피소드 종료 조건·844 관측/8577 행동 구조는 유지한다.

## 단계별 보완

| 단계 | 균형 샘플링 기준 | 학습 항목(변형 포함) | 기존 평가 | 새 검증 |
| --- | --- | ---: | ---: | ---: |
| 0 포획 | 난이도별 예시 포획 기물 종류 | 6,494 | 192 | 192 |
| 1 포획·방어 | 안전한 이득 / 유리한 교환 / 포획 선택 | 5,990 | 192 | 96 |
| 2 메이트 | 메이트 인 1 / 인 2 | 3,945 | 128 | 64 |
| 3 엔드게임 | KQK / KRK | 4,028 | 128 | 64 |
| 4 중반 | 기물 수 16~20/21~24/25~28 × ECO 계열 A~E 등 | 8,373 | 256 | 64 |
| 5 전체 대국 | 3수/4수 시작 × ECO 계열, 표준 초기 배치는 별도 확률 | 1,025 | 129 | 64 |
| 합계 | | **29,855** | **1,025** | **544** |

각 묶음을 먼저 균등 선택하고 그 안에서 배치를 선택한다. 0단계의 여러 기물로 해결 가능한 문제는 기록된 예시 포획 기물로 묶지만, 성공 판정은 다른 유리한 포획도 허용한다. 0-C에서는 킹처럼 유리한 재포획 교환 유형에 해당하지 않는 기물 묶음은 만들지 않는다. Inspector의 **Balance Curriculum Samples**로 균형 샘플링을 끌 수 있다. 기본값은 켬이다.

5단계의 Standard Start Probability는 계속 0.2다. 오프닝 표본은 기본 80%이며, 기존 3수·4수 수량과 계열별 묶음을 사용한다. 캐슬링을 포함한 정상 오프닝 규칙을 유지하기 위해 이 단계는 좌우 반전하지 않는다. 중반도 캐슬링 권리가 있는 위치는 좌우 반전하지 않는다.

## 자료 추가와 대칭 변형

Lichess 2013년 1월 원본 49,719경기를 스캔해 이전 자료에서 사용하지 않은 경기로부터 다음을 추가했다.

- 0-A 학습 보강: 킹·폰·나이트·비숍·룩·퀸의 예시 포획 위치 각각 32개, 총 192개.
- 모든 단계의 새 검증 위치 544개. 기존 학습·평가·Legacy 경기와 원본 경기 단위로 분리한다.
- 엔드게임 검증은 한 경기에서 최대 4개 위치를 사용하므로 위치들이 모두 독립 경기인 것은 아니다.

기존 평가와 새 검증 위치를 먼저 보호한다. 색 반전과 합법적 좌우 반전까지 같은 위치로 묶어 검사했고, 새 학습에서 충돌하는 기존 항목 36개를 제외했다. 원본 PGN·positions.jsonl은 이전 실험 재현용으로 유지한다. 현재 자료는 **Data/Curriculum/Generalization/positions.jsonl**이다. 변형은 학습 분할에만 추가한다. 총 13,314개 좌우 변형이 추가되며 이것을 독립적인 원본 경기 수로 해석하면 안 된다.

좌우 반전은 0~4단계에서 캐슬링 권리가 없는 위치만 사용한다. 전체 경기 앞부분에 캐슬링이 있을 수 있으므로 마지막 비가역 수(폰 이동·포획·캐슬링 권리 변화 등) 직후의 FEN부터 이력을 다시 구성하고 좌우로 변환한다. 이전 위치는 반복될 수 없어 반복 판정에 필요하지 않다. 50수 카운터는 보존하며 이후 반복 이력은 그대로 재생한다. 생성 시 반복 상태·합법성·비종료 상태와 포획 관계를 검증한다. 에피소드의 턴 수와 보상은 선택 위치에서 0으로 시작한다.

JSONL 대국 기록의 sourceStartPly는 원본 경기의 시작 반수이며, historyOffset은 보존할 필요가 없는 앞부분의 길이다. sourceHorizontal과 curriculumStratum으로 변형·샘플링 유형을 추적한다. historyInitialFen에서 historyMoves, moves를 순서대로 재생하면 대국을 복원할 수 있다.

## 평가와 승급

`config/chess_evaluation.yaml`은 새 경로를 사용하며 evaluation_version은 5다.

- 기존 평가: 0단계 난이도별 64개 양색, 1~5단계별 128개 양색.
- 학습 표본 평가: 0단계 난이도별 64개 양색, 1~5단계별 32개 양색. 변형 포함 자료에서 유형별로 선택한다. 전체 학습 성공률이 아니다.
- 새 검증: 현재 및 이전 단계/난이도별 32개 양색(64회). 유형별 균형 선택한다.
- 기존 평가와 새 검증이 모두 기존 성공률 기준을 넘어야 승급한다. 이전 단계 유지 기준도 두 자료에 적용한다.
- 1~3단계는 각 과제 유형도 동일 기준을 통과해야 한다. 예를 들어 KQK만 잘 풀어 KRK 실패를 평균에 숨길 수 없다. 유형별 최소 평가 횟수 기본 16회다.
- 4단계의 세부 중반 유형과 0단계의 희소 기물별 결과는 표본 수가 작을 수 있으므로 개별 강제 승급 기준 대신 유형별 지표로 표시한다. 5단계는 마지막 단계로 추가 승급은 없다.
- 새 검증 역시 승급에 반복 사용되므로 **최종 블라인드 테스트가 아니라 검증 세트**다. 최종 기력 평가는 별도 미사용 자료가 필요하다.

전 단계 TensorBoard 지표:

- `Evaluation/LessonN/TrainingSuccess`
- `Evaluation/LessonN/Success`
- `Evaluation/LessonN/GeneralizationGap`
- `Evaluation/LessonN/IndependentSuccess`
- `Evaluation/LessonN/IndependentGap` (학습 표본 성공률 − 새 검증 성공률)
- `Evaluation/LessonN/Strata/.../Success`

포획 난이도별 `Evaluation/CaptureN/IndependentSuccess`도 추가했다. 일반화 격차가 0.2를 넘으면 실행 로그에 진단 안내를 출력한다. 학습 표본과 기존 평가 표본의 구성·비중이 완전히 같지는 않으므로 Gap은 진단 지표이며 그 수치 하나만으로 원인을 단정하지 않는다.

평가 직전 Replay Buffer 저장 생략은 유지한다. 추가 검증에 필요한 평가 시간은 늘어날 수 있다.

## 적용

이번에는 Unity 런타임과 리소스도 바뀌었으므로 **Training 플레이어를 다시 빌드**한다. 데이터·평가 fingerprint가 바뀌므로 **새 run-id**를 사용한다. 기존 모델 구조는 유지했으므로 가중치는 초기값으로 가져올 수 있다.

```powershell
python Tools/TrainChessSuccess.py config/chess_sac.yaml --run-id=generalization_v1 --initialize-from=curriculum_3 --env=output/chess-training/ChessTraining.exe --no-graphics --torch-device=cuda --num-envs=4 --time-scale=30
```

num-envs와 time-scale은 예시다. 비교 실험은 이전 실행과 동일한 병렬 설정에서 측정하는 것이 좋다. --initialize-from은 가중치를 가져오며 새 커리큘럼은 0-A부터 시작한다. 기존 실행에 --resume으로 새 자료를 섞지 않는다. 현재 새 검증 위치는 이전 자료의 학습 배치 및 그 대칭과도 겹치지 않게 수집했다.

## 재현

```powershell
.venv-training/Scripts/python.exe Tools/CollectGeneralizationPositions.py output/training-validation/pgn-source/lichess-2013-01.pgn.zst
.venv-training/Scripts/python.exe Tools/PrepareGeneralizationDataset.py
.venv-training/Scripts/python.exe Tools/VerifyGeneralizationDataset.py
```

BuildCurriculumDataset.py도 추가 자료가 있으면 PrepareGeneralizationDataset 경로를 사용한다. 원본 PGN 검증은 VerifyCurriculumPgn.py로 별도 실행할 수 있다. 현재 데이터의 수량·분할·변형 수·hash는 Generalization/manifest.json과 collection.json에 기록한다. 자료 출처와 CC0 라이선스는 기존 Data/Curriculum/README.md를 따른다.

## 변경 전 모델의 새 기준 출발점

진단에 사용한 500,253-step 모델 그대로 검사했다. 새 학습 표본 성공률 68.0%, 기존 평가 51.6%, 새 검증 35.9%다. 기존 평가 결과는 그대로 재현됐다. 새 Training Success가 낮아지고 기존 평가와의 Gap이 작아진 것은 표본 구성 변경 때문이며 모델이 좋아진 결과가 아니다. 새 검증과의 격차도 함께 확인해야 한다. 장기 학습으로 실제 개선되는지는 별도 실험이 필요하다.
## 검증 결과 (2026-10-02)

- 전체 31,424개 항목의 합법적 이력 재생, 대칭 대응, 원본 경기·대칭 위치 분리 및 학습 전용 리소스 포함 검사 통과.
- Python 테스트 25개, C# 핵심 규칙 테스트 47개 통과.
- Unity EditMode 89/89, PlayMode 24/24, Unity/Python 관측·행동 마스크 비교 98개 통과.
- 분리된 검증 프로젝트의 Windows 학습 플레이어 빌드 성공.
- CUDA 실행 generalization-check-20261002는 기존 500,253-step 체크포인트 복사본에서 초기화하고 857 step에 exit 0으로 종료했다. 별도 검증 설정의 임계값 0으로 0-A→0-B→0-C→1→2→3→4→5 전환과 전 단계 지표·ONNX 저장을 확인했다. 본 학습 설정의 임계값은 기존 값을 유지하며, 이 실행은 기력 개선 실험이 아니다.
