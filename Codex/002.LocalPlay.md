# 로컬 체스 플레이

요청 확인: 이번 단계는 네트워크 대국이 아닌, 한 화면에서 사람이 백·흑을 번갈아 조작하는 대국이다.

## 실행

1. Unity 6000.3.10f1에서 스크립트와 자산 가져오기가 끝날 때까지 기다린다.
2. `Assets/Scenes/SampleScene.unity`를 열고 Play를 누른다. 이 씬에서만 `LocalChessBootstrap`이 화면과 대국 제어기를 구성한다.
3. 현재 차례의 말을 클릭하고 초록색 목적지를 클릭한다. 마지막 줄에 도달한 폰은 Queen/Rook/Bishop/Knight 중 선택해야 턴이 넘어간다.

스프라이트 설정 자산은 `Assets/Resources/ChessArt.asset`이다. 누락되면 에디터에서 자동 생성하며, `ChessBot > Prepare Local Chess` 메뉴로 다시 연결할 수도 있다. 제공된 `Assets/Sprites`의 기존 분할 스프라이트를 그대로 참조한다. 씬이나 Inspector 수동 연결은 필요 없다.

## 조작

- `New game`: 진행 중인 판을 버리고 초기 배치로 새 대국을 시작한다.
- `Flip board`: 백·흑 관점을 뒤집는다. 규칙 좌표와 턴은 그대로 유지한다.
- `Resign`: 현재 차례의 진영이 기권한다.
- `Claim draw`: 현재 위치가 3회 반복 또는 50수 조건을 만족할 때 활성화된다.
- `Claim draw with next move`: 버튼을 누른 뒤 조건을 충족할 예정 수를 선택한다. 유효하면 수를 실제로 두지 않고 무승부로 종료한다. 무효하면 보드·턴·이력을 유지한다. 버튼을 다시 누르면 취소한다.

UI 문구는 현재 영어이며 마우스/터치 클릭용이다. 이동 입력은 Input System의 uGUI 입력 모듈을 사용한다.

## 구현 경계

- Core: Unity 의존 없는 상태·FEN·기물 행마·킹 안전성·특수 수·반복 키.
- Application: 대국 식별자와 턴 버전 검사, 상태 소유, 이력, 결과 및 종료 이벤트.
- Presentation: 스프라이트 보드, 선택·하이라이트·승격·무승부 선언 입력. 보드 배열을 변경하지 않는다.
- Bootstrap: 로컬 화면 구성과 종료 기록 저장. 별도 학습 씬에는 자동 실행하지 않는다.

완료한 대국의 초기 FEN, UCI 수 목록, 승격, 종료 사유, 승자, 예정 선언 수, UTC 종료 시각을 `Application.persistentDataPath/ChessGames/<대국 ID>.json`에 저장한다. 현재 플레이어 설정의 회사/제품 이름에 따라 실제 경로가 달라진다. 저장 실패는 화면과 Console에 표시하며 이미 결정된 결과를 되돌리지 않는다. 진행 중 새 대국으로 버린 판은 완료 기록으로 저장하지 않는다.

## 규칙 범위와 제한

기본 이동·포획, 체크·체크메이트·스테일메이트, 양 진영 양쪽 캐슬링, 앙파상, 네 종류 승격, 3회 반복/50수 선언 및 5회 반복/75수 자동 무승부를 처리한다. 반복 키는 합법적인 앙파상 가능성만 포함하며 체크메이트가 75수 규칙보다 우선한다.

Dead position은 킹만 남은 경우, 킹+비숍/나이트 대 킹, 같은 색 칸의 비숍만 남은 경우처럼 확실한 사례만 판정한다. 임의의 봉쇄 포지션에 대한 완전한 판정기는 구현하지 않았다. 따라서 README의 **표준 규칙 전체 완료 및 학습 시작 기준을 충족했다고 간주하지 않는다.** 네트워크, Agent 대전·학습, 시계, 합의 무승부, 기보 불러오기는 이번 구현 범위가 아니다.

## 검증

- Unity Test Runner의 EditMode: `ChessBot.Chess.Tests`.
- PlayMode: `ChessBot.Chess.PlayModeTests`에서 실제 화면 생성·32개 기물·양 진영 이동·보드 회전·새 대국을 검사한다.
- 에디터 연결 없이 재현할 수 있는 보조 검증: `Codex/ValidateLocalChess.ps1`. 설치된 Unity 컴파일러·참조 DLL로 어셈블리를 각각 컴파일하고 순수 규칙/입력 테스트를 실행한다. Unity가 다른 경로에 설치됐으면 `-UnityData`를 지정한다.
- 초기 배치 perft 깊이 1/2/3 = 20/400/8902, Kiwipete 깊이 1/2 = 48/2039를 검증한다. 무승부와 제어기 계약은 별도 테스트로 검사한다.

검증 실행 결과는 별도 완료 보고에 기록한다. 테스트 코드의 존재 자체가 실행 성공을 의미하지 않는다.
