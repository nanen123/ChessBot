# ChessAgent와 초기 SAC 학습

## 씬 구분

| 씬 | 용도 |
| --- | --- |
| `Assets/Scenes/LocalPlay.unity` | 기존 보드 UI에서 사람이 백·흑을 번갈아 조작 |
| `Assets/Scenes/Training.unity` | White Agent와 Black Agent의 SAC Self-Play, UI 없이 규칙 엔진만 실행 |
| `Assets/Scenes/SampleScene.unity` | 이전 작업과의 호환을 위해 유지한 로컬 대국 씬 |

일반 빌드의 첫 씬은 LocalPlay다. Training은 일반 빌드 목록에서 비활성화되어 있으며, `ChessBot > Training > Build Windows Training Player` 메뉴는 Training만 포함한 실행 파일을 `output/chess-training/ChessTraining.exe`에 만든다. 씬이 누락되면 `ChessBot > Training > Create Missing Scenes`로 생성한다. 이 메뉴는 이미 존재하는 씬을 덮어쓰지 않는다.

Training 씬의 `Chess Training Environment`에서 보상과 최대 반수 수를 조절한다. 두 Agent의 Behavior Name은 `ChessV1`, Team ID는 백 0·흑 1, 개별 Max Step은 0이다. `DecisionRequester`를 추가하면 안 된다. 학습기가 연결되지 않으면 대국을 멈추고 안내를 출력한다. `Allow Heuristic Preview`를 켜면 무작위 합법 수로 연결 상태를 확인할 수 있지만 **이 모드는 학습 또는 학습된 모델이 아니다.**

## 초기 보상

| 사건 | 당사자 | 상대 |
| --- | --- | --- |
| 기물 포획 | +0.1 | -0.1 |
| 승리 / 패배 | +1 | -1 |
| 무승부 | 0 | 0 |

기물 종류별 가중치, 체크 보너스, 이동·시간 패널티, 위치 평가, 승격 보너스는 넣지 않았다. 앙파상도 실제로 잡힌 폰에 대해 한 번 보상한다. 승리하는 수가 동시에 포획이면 포획 보상과 종료 보상이 모두 적용된다. 위 값은 초기 기본값이며 Inspector에서 변경할 수 있다.

대국당 기본 512 ply(양측 합계 반수) 제한은 학습 실행 길이를 제한하는 장치다. 이 한도에 도달하면 추가 보상 없이 두 Agent에 `EpisodeInterrupted()`를 호출한다. 이를 체스 무승부나 패배로 기록하지 않는다. 정상 종료는 최종 상태에서 양측 종료 보상을 반영하고 두 `EndEpisode()`를 호출한 후, 다음 Academy 단계에서 보드·이력·대국 ID를 한 번만 재설정한다.

## 액션 마스킹과 관측

한 개의 이산 행동 분기에 **8,577개**의 고정 의미 행동을 사용한다.

- 0–4,095: 일반 수 `from * 64 + to`.
- 4,096–4,287: 백·흑, 출발 파일, 전진/대각 방향, 네 종류 승격을 분리한 승격 수.
- 4,288–8,575: 대응하는 예정 수로 무승부 선언.
- 8,576: 현재 포지션에서 무승부 선언.

현재 차례마다 기존 `ChessRules`의 합법 수와 제어기의 무승부 선언 검사를 사용해 허용 행동을 만든다. `WriteDiscreteActionMask`가 나머지 모든 행동을 차단한다. 독립적인 출발/도착 분기가 아니므로 불법 조합이 남지 않는다. 범위를 벗어난 승격 등 예약된 인덱스도 항상 비활성화된다. 종료된 보드에는 결정을 요청하지 않는다. 잘못된 행동을 받으면 즉시 학습 대국을 정지하며, 임의의 다른 수로 바꾸거나 별도 처벌 보상을 주지 않는다. ML-Agents의 종료 응답은 기본값 0으로 전달될 수 있으므로, 오류 기록은 다음 프레임에도 Academy가 계속 실행될 때 남긴다.

관측은 **844개**다. 자기/상대별 6종 기물의 64칸 one-hot, 자기 색·차례, 캐슬링 권리, 앙파상 후보, 반수 카운터, 현재 위치 반복 횟수, 현재·예정 수 선언 가능 여부, 학습 반수 제한 진행률을 포함한다. 백·흑 모두 절대 좌표 `a1=0, h8=63`을 사용한다. 전체 반복 이력은 관측하지 않으므로 v1은 부분 관측 정책이다. 선언 가능성 자체는 정확한 이력으로 마스킹한다.

스키마는 `config/chess_v1.schema.json`에 기록했다. 관측 또는 행동의 의미가 바뀌면 Behavior 이름과 스키마 버전을 함께 변경해야 한다. 이 작업은 학습 환경 구성까지이며, ONNX를 사람 대 Agent UI에 연결하거나 모델 호환성을 검증해 로딩하는 기능은 후속 범위다.

## 실행

현재 준비된 환경에서는 프로젝트 폴더에서 다음과 같이 실행한다.

```powershell
# 짧은 연결/학습/저장 확인
.\Codex\TrainChess.ps1 -RunId chess-smoke-new -Smoke

# 초기 SAC Self-Play 학습
.\Codex\TrainChess.ps1 -RunId chess-first

# 중간에 중단한 동일 설정의 학습 재개
.\Codex\TrainChess.ps1 -RunId chess-first -Resume
```

새 PC/작업 사본에서는 먼저 `Codex/SetupTraining.ps1`을 실행한다. uv가 설치되어 있어야 하며, Python 3.10.12와 CPU 학습 패키지를 프로젝트용 경로에 설치한다. Python 3.12/3.13 환경과 섞지 않는다. 설치된 버전은 `config/requirements-training-lock.txt`로 고정한다. 그 다음 Unity의 학습 빌드 메뉴를 실행한다.

에디터에서 학습하려면 아래 명령을 먼저 실행하고, Unity에서 **Training 씬을 열어 Play**를 누른다.

```powershell
.\Codex\TrainChess.ps1 -RunId chess-editor -Editor
```

기존 run ID는 자동 덮어쓰지 않는다. 학습 결과와 ONNX는 `results/<run-id>/`에, 관측·행동 스키마, 설정과 패키지 버전은 `results/metadata/<run-id>/`에 저장한다. `-Resume`은 스키마 일치를 검사한다. 같은 스키마라도 네트워크 구조가 다른 smoke 설정과 일반 설정의 체크포인트를 혼용하면 안 된다. `Ctrl+C`로 학습을 종료하면 ML-Agents가 종료/저장 절차를 수행한다.

진행 상황은 아래 명령으로 확인할 수 있다.

```powershell
.\.venv-training\Scripts\tensorboard.exe --logdir results
```

대국별 UCI 수 목록, 종료 사유/중단 여부와 양측 누적 보상은 `Application.persistentDataPath/ChessTraining/*.jsonl`에 저장한다. 저장 실패는 경고로 알리며 게임 상태는 유지한다.

### CUDA 학습 및 CPU/CUDA 혼합 오류 수정

`config/chess_sac.yaml`의 기본 장치는 사용자의 GPU 학습 환경에 맞춰 `cuda`로 변경했다. 기존 `TrainChess.ps1`은 프로젝트의 CPU 전용 `.venv-training`을 사용하고 `--torch-device cpu`를 명시하므로 CPU 검증용으로 유지된다. GPU 학습은 CUDA용 PyTorch가 설치된 Conda 환경에서 직접 실행한다.

```powershell
conda activate mlagents
mlagents-learn config/chess_sac.yaml --run-id=chess-gpu --env=output/chess-training/ChessTraining.exe --no-graphics --torch-device=cuda
```

사용자 환경은 ML-Agents 1.1.0, PyTorch 2.2.2+cu121, RTX 4050 Laptop GPU다. ML-Agents 초기 import가 CUDA를 기본 텐서 장치로 선택한 뒤 설정에서 CPU를 선택하면, 이 버전의 `set_torch_config`는 기본 텐서 장치를 CPU로 되돌리지 않는다. 모델은 CPU로 이동하지만 ONNX dummy 입력은 CUDA로 만들어져 저장 시 `wrapper_CUDA_addmm` 오류가 발생한다. 같은 844 관측/8577 행동 정책으로 CPU 설정의 오류를 재현했고, CUDA 설정에서는 양측 장치가 일치하여 ONNX export가 통과했다. Conda 패키지 소스는 수정하지 않았다.

기존 학습 결과는 삭제하지 않는다. 새 학습은 새 run ID로 실행하고, 유효한 체크포인트가 있는 기존 학습을 이어갈 때만 해당 run ID와 `--resume`을 사용한다.
실제 CUDA smoke run `chess-cuda-fix-check`도 성공했다(exit 0). 256단계 설정의 rollout 경계인 step 320까지 진행하며 SAC 학습, 체크포인트·replay buffer·ONNX 저장을 완료했고 ONNX checker를 통과했다.
