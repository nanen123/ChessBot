# ChessBot Curriculum

## 현재 적용 상태

전 단계 균형 샘플링·합법적인 좌우 변형·새 검증 자료가 적용되었다. 현재 학습 리소스는 변형 포함 29,855개다. 아래 기존 수집 표는 증강 이전 원본 수량이며, 최신 수량·승급 조건·새 실행 방법은 [008.Generalization.md](008.Generalization.md)를 따른다.

## 실제 PGN 학습 연결

현재 기본 Position Source는 **Pgn Training**이다. 각 단계는 아래 확장 표의 학습 배치 중 선택한다. 전체 train 16,385개와 eval 1,025개를 분리했고 eval은 런타임 리소스에 포함하지 않는다. 학습은 실제 경기의 지정 위치에서 Self-Play로 이어진다. 사람의 이후 수순을 정답으로 따라 하는 모방 학습은 아니다.

`Tools/BuildCurriculumDataset.py`가 `Data/Curriculum/*.train.pgn`을 검증하고 `Assets/Resources/ChessCurriculumTraining.json`으로 변환한다. 변환된 16,385개 학습 항목을 이미 포함했으므로 처음에는 변환 명령 없이 Training 플레이어를 다시 빌드하면 된다. 실행 파일에는 필요한 데이터가 포함되며 인터넷·원본 PGN·Python chess 패키지 없이 실행된다.

현재 소스는 [실제 경기 자료 안내](../Data/Curriculum/README.md)의 선정 기준을 따른다. 아래 단계 표의 소수 수제 배치는 **Position Source = Inspector Fen**으로 선택하는 대체 데이터다. 단계별 종료 조건·보상·반수 한도는 두 소스에 공통 적용한다. 세부 난이도의 데이터 분리와 복습 샘플링은 Pgn Training 모드에서 적용한다. Pgn Training에서는 Lessons의 Positions 배열을 사용하지 않으며 나머지 설정은 계속 Inspector에서 조절한다.

- 0~4단계: 해당 train 기보의 시작 수순까지 재생해 초기화하고 색을 번갈아 반전한다. 캐슬링·앙파상·50수 카운터·반복 이력을 보존한다.
- 기보 이전 수순의 포획에는 보상을 주지 않는다. 에피소드 반수·승리 보상 감소·반수 제한·관측 진행률은 선택한 위치에서 **0부터** 시작한다.
- 5단계: 80%는 양쪽이 각각 3~4수 둔 실제 오프닝(6/8 ply), 20%는 표준 초기 배치에서 시작한다. 선택 위치 이후 수순은 Agent가 결정한다.
- eval 데이터, 잘못된 단계·난이도 및 빈 묶음은 로드 시 거부한다. 전체 PGN은 생성·검증 도구에서 검사하며, Unity는 각 샘플을 처음 선택할 때 수순·FEN·종료 여부를 다시 검증하고 공유 캐시한다. 잘못된 샘플은 오류로 중단한다. 수제 배치로 조용히 대체하지 않는다.
- JSONL 기록에는 datasetId, sourceGame, sourceStartPly, sourceMirrored, historyInitialFen, historyMoves가 추가된다. historyMoves 후 moves를 재생하면 반복 이력을 포함해 학습 대국을 복원할 수 있다.
- 데이터 확장 후 프로젝트 루트에서 `.venv-training/Scripts/python.exe Tools/BuildCurriculumDataset.py` 실행 → Unity 재빌드가 필요하다. 생성기 의존성은 데이터 안내를 따른다.

현재 YAML은 단계 0 고정값을 제공하며 성공률 기반 실행기가 승급을 제어한다. 0단계 첫 수 과제와 초기 단계 반복 벌점은 아래 규칙을 따른다. 새 실험은 `--run-id=pgn-curriculum-first`처럼 기존 결과와 다른 이름을 사용한다.

## 실행과 공통 원칙

`config/chess_sac.yaml`은 SAC Self-Play와 6단계 커리큘럼을 사용한다. 새 코드를 포함하도록 **Training 실행 파일을 다시 빌드**한 뒤 실행한다.

```powershell
conda activate mlagents
python Tools/TrainChessSuccess.py config/chess_sac.yaml --run-id=pgn-curriculum-first --env=output/chess-training/ChessTraining.exe --no-graphics --torch-device=cuda
```

단계 번호는 0~5다. Python의 `curriculum_stage` 값을 각 환경이 **새 에피소드 시작 시에만** 읽는다. 성공률 승급 실행기는 승급 시 전체 환경을 reset해 새 단계를 함께 적용하며 시작 포지션은 각각 무작위로 선택한다. 0~4단계는 각 환경에서 색을 번갈아 반전해 양쪽이 문제의 주인공 역할을 경험한다. 5단계는 보드를 색 반전하지 않고 표준 배치 또는 6/8-ply 오프닝에서 백 차례로 시작한다.

두 Agent가 같은 보드를 사용하고, 종료 시 양측 에피소드를 함께 종료한 뒤 다음 Academy 단계에서 보드를 한 번 초기화한다. 모든 단계에서 합법 수 Action Masking과 기존 특수 규칙을 유지한다. 이번 구현은 기존 모델과 같은 관측 844개·행동 8577개를 유지하며 단계 번호를 별도 관측으로 추가하지 않는다. 전체 반복 이력을 관측하지 않는 기존 한계에 더해 초기 과제의 목표도 직접 관측하지 않으므로 단계 간 학습 간섭 가능성이 있다.

## 단계 / 학습 내용 / 종료 조건 / 보상

아래의 '주인공'은 해당 시작 포지션에서 먼저 움직이는 색이다. 반대 색도 같은 정책으로 Self-Play하며 별도의 스크립트 상대를 사용하지 않는다.

| 단계 | 학습 내용과 시작 포지션 | 에피소드 종료 조건 | 보상 |
| --- | --- | --- | --- |
| 0. 첫 수 유리한 포획 | 실제 PGN의 세 난이도(4~20기물). 수제 대체 배치 3개도 제공 | 첫 합법 수 1 ply 직후 종료. 실제 체스 종료 우선 | 상대의 모든 한 수 응수 뒤에도 순기물 이득이 양수이고 즉시 메이트를 허용하지 않는 포획이면 공통 포획 보상과 +0.1. 그 외 -0.1이며 불리한 포획의 즉시 포획 보상은 억제. 상대에게 반대 부호 |
| 1. 포획과 방어 | 안전한 이득·유리한 교환·포획 선택의 실제 PGN 배치 | 12 plies 또는 실제 체스 종료. 첫 포획 직후에는 끝내지 않아 응수·재포획을 경험 | 공통 포획 보상. 12 plies에서 주인공의 순포획 점수 >0이면 +0.1, <0이면 -0.1, =0이면 0. 상대에게 반대 부호 |
| 2. 메이트 인 1·2 | 다양한 기물의 실제 메이트 인 1 및 강제 메이트 인 2 포지션 | 실제 승패·무승부 또는 3 plies. 메이트 인 1에 실패해도 남은 3 plies 범위 안에서 계속 진행 | 체크메이트는 공통 승패 보상만 적용. 3 plies까지 정상 종료 없이 메이트에 실패하면 주인공 -0.1, 상대 +0.1. 별도 성공 보너스 기본값은 0 |
| 3. 간단한 엔드게임 | 킹+퀸 대 킹, 킹+룩 대 킹 | 실제 체스 종료 또는 100 plies 중단 | 공통 포획·승패·정상 무승부 보상. 한도 중단에는 종료 보상 없음 |
| 4. 중반 대국 | 실제 경기의 20~50-ply 위치, 16~28기물, 기물 점수 차이 2 이하 | 실제 체스 종료 또는 256 plies 중단 | 공통 보상. 한도 중단에는 종료 보상 없음 |
| 5. 전체 대국 | 실제 오프닝 80% + 표준 초기 배치 20% | 실제 체스 종료 또는 512 plies 중단 | 공통 보상. 한도 중단에는 종료 보상 없음 |

0~2단계의 문제 한도는 **과제 자체의 종료**이므로 `EndEpisode()`를 사용한다. 과제 성공/실패는 체스 승리/패배/무승부로 기록하지 않는다. 3~5단계 한도는 진행 중 대국의 시간 제한이므로 `EpisodeInterrupted()`를 사용한다. 어느 단계든 정상 체스 결과가 같은 수에 발생하면 과제 한도보다 우선하며 추가 과제 보상을 중복 적용하지 않는다.

Inspector Fen 모드의 중반 FEN에는 캐슬링 권리·차례·반수 카운터를 보존하지만 이전 반복 이력은 없다. 기본 Pgn Training 모드는 이전 수순의 반복 이력도 보존한다. 확장 데이터의 수량은 아래 표를 따른다. 자료 수량만으로 학습 성공이나 실제 기력을 보장하지 않는다.

## 공통 보상

- 포획: `Capture Reward × 잡힌 기물 점수`, 상대에게 같은 크기의 음수. 기본 배율 0.05, 폰 1 / 나이트·비숍 3 / 룩 5 / 퀸 9. 되잡힘은 나중의 별도 포획으로 처리한다.
- 승리: `Win Reward + (Minimum Win Reward - Win Reward) × Clamp01(진행 plies / 감소 기준 plies)`. 기본 1에서 0.5로 감소한다.
- 패배: `-승리 보상 × Loss Reward Multiplier`, 기본 배율 1.
- 정상 무승부: 백 -0.2 / 흑 +0.2. 스테일메이트·반복·수순 규칙·기물 부족 등 실제 체스 무승부에만 적용한다.
- 커리큘럼 실패·중립 종료·학습 한도 중단을 정상 무승부로 간주하지 않는다.
- 포획 보상과 종료 보상은 누적된다. 일률적인 매 수 벌점, 체크 보너스, 승격 자체 보너스는 없다. 0~2단계에는 아래의 반복 벌점만 추가한다.

`Win Reward Decay Plies = 0`이면 **현재 에피소드의 단계별 반수 한도**를 감소 기준으로 사용한다. 모든 단계에서 동일한 시간 척도를 원하면 512 등으로 명시한다. 한쪽의 한 수가 1 ply이며 두 색이 각각 한 번 두면 2 plies다.

## Inspector에서 조절하기

`Chess Training Environment`의 Curriculum 섹션:

- **Use Curriculum**: 끄면 기존 표준 초기 배치와 Maximum Plies를 사용한다.
- **Position Source**: 기본 Pgn Training은 수집한 학습 기보를 사용한다. Inspector Fen은 아래 Positions 배열을 사용한다.
- **Preview Lesson**: Python이 `curriculum_stage`를 보내지 않을 때 사용할 단계(0~5). 에디터 무작위 미리보기에는 기존 Allow Heuristic Preview도 켜야 한다.
- **Lessons**: 반드시 6개. 각 항목의 Name, Ending, Maximum Plies, Success Reward, Failure Penalty, Positions(FEN 배열)를 조절한다. 배열 순서가 YAML의 0~5와 대응한다.
- **Ending = First Move Favorable Capture**: 항상 첫 수 1 ply에 종료한다. 이 모드에서는 Maximum Plies 값을 늘려도 종료 시점이 늘어나지 않는다.
- **Success Reward / Failure Penalty**: 0~2단계의 비체스 과제 종료에만 적용. Failure Penalty는 양수 크기를 입력한다. 실제 체스 종료에는 공통 종료 보상을 적용한다.

단계별 설정은 시작할 때 유효성 검사한다. 이미 종료된 포지션이나 차례가 아닌 쪽의 킹이 체크 상태인 FEN은 거부한다. 0~4단계의 입력 FEN은 기본적으로 문제를 풀 쪽이 먼저 움직이도록 작성한다. 매 단계의 최대 반수는 관측의 진행률 분모로도 사용한다. Inspector 변경은 Play 전 적용하며 실행 파일 학습에는 재빌드가 필요하다.

## 성공률 기반 단계 전환

2026-10-01부터 진행률 기반 승급을 제거했다. 자동 평가, 성공률·이전 단계 유지 기준, 재개 방법은 [006.AutomaticEvaluation.md](006.AutomaticEvaluation.md)를 따른다. 기본적으로 50,000 step마다 평가하고 최소 100,000 step 학습 후 연속 2회 통과해야 승급한다. 승급 순간에는 전체 환경을 reset하고 이전 과제 replay buffer를 비운다. 이에 승패 보상은 부여하지 않는다.

일반 mlagents-learn만 실행하면 단계 0에 머문다. 위의 TrainChessSuccess.py 실행 명령을 사용한다. 단계별 종료 조건과 보상은 이 문서의 표를 따른다.

## 반복 억제 및 첫 수 과제 개편 (2026-10-01)

Early Lesson Repetition 설정은 0~2단계에만 적용한다. 동일한 보드·차례·캐슬링 권리·합법 앙파상 상태의 두 번째 방문부터 움직인 Agent에게 기본 -0.005를 준다. 상대에게 보상을 옮겨 주지 않는다. 에피소드 시작 위치는 1회로 세며 PGN 이전 이력은 벌점 방문 횟수에 포함하지 않는다. 실제 무승부 판정의 PGN 이력은 계속 보존한다.

- Repetition Penalty: 0.005. 0이면 비활성화.
- Repetition Penalty From Occurrence: 2. 최소 2.
- Maximum Repetition Penalty Per Agent: 에피소드당 각 Agent 최대 0.05.
- 3~5단계, 커리큘럼 비활성 상태, 실제 체스 종료 수 및 무승부 청구에는 벌점을 주지 않는다.
- 반복 수 자체를 마스킹하지 않는다. 합법 수와 무승부 청구는 계속 선택할 수 있다.
- TensorBoard: Chess/RepeatedPositions, Chess/RepetitionPenalty. 첫 지표는 모든 단계의 에피소드 내 재방문 횟수다.

0단계의 유리한 포획은 잡은 기물 점수 + 승격 증가분에서 상대의 모든 합법 응수 중 최대 포획·승격 이득을 뺀 값이 양수인 경우다. 상대의 즉시 체크메이트가 하나라도 있으면 실패다. 최선의 장기 전술을 증명하는 기준은 아니다. 첫 수로 끝나는 과제에서 나쁜 희생의 포획 보상이 실패 벌점을 상쇄하지 않도록, 이 과제의 불리한 포획에는 즉시 포획 보상을 주지 않는다. 1~5단계 포획 보상은 유지한다.

기존 프리팹의 Capture Reward 0.1, 백/흑 무승부 0 설정은 보존했다. 위 공통 보상 수치는 코드 기본값이며 실제 학습은 Inspector 값을 사용한다. 새 학습에는 Training 실행 파일을 재빌드하고 새 run-id를 사용한다. 변경된 데이터와 평가 설정으로 이전 성공률 상태를 --resume 할 수 없다. 기존 가중치는 새 run에 --initialize-from=이전run으로 사용할 수 있다.

## 0단계 데이터 확장과 세부 난이도 (2026-10-01)

훈련 배치 128/128 성공, 별도 평가 4/32 성공의 과적합을 보완하기 위해 0단계를 아래 순서로 나눴다. `curriculum_stage`는 기존 0~5를 유지하고 0단계 안에서 `capture_difficulty`가 0→1→2로 증가한다. 이후 기존 1단계로 넘어간다.

| 표시 | capture_difficulty | 학습 내용 | train / eval | 승급 / 유지 성공률 |
| --- | --- | --- | --- | --- |
| 0-A 공짜 포획 | 0 | 전체 4~6기물. 포획한 말을 즉시 되잡을 수 없는 유리한 포획 | 1,024 / 64 | 90% / 80% |
| 0-B 안전한 포획 | 1 | 7~12기물. 방해 기물 속에서 즉시 되잡히지 않는 유리한 포획 | 1,024 / 64 | 85% / 75% |
| 0-C 유리한 교환 | 2 | 최대 20기물. 되잡혀도 순이득이 남는 포획. 즉시 되잡히지 않는 다른 유리한 포획이 없는 배치 | 1,024 / 64 | 85% / 75% |

모두 실제 PGN의 위치이며 소수 기물을 임의로 삭제해 만든 배치가 아니다. 모든 후보는 기존 두 반수 전술 기준을 만족한다. 여기서 공짜·안전은 즉시 되잡힘에 대한 표현이며 장기 전술까지 안전함을 보장하지 않는다. 각 난이도의 종료는 첫 수 1 ply, 성공/실패와 포획 보상 규칙은 기존 0단계와 같다. 정상 체스 종료가 우선한다.

각 세부 난이도에서 최소 100,000 step과 연속 두 번의 평가 통과를 요구한다. 이전 난이도도 유지 기준을 만족해야 한다. 승급할 때 에피소드와 SAC replay buffer를 reset하고 다음 난이도에 진입한다. 별도 관측·행동 차원 변경은 없다.

Inspector의 Preview Capture Difficulty는 Python이 값을 보내지 않을 때 쓸 0~2 난이도다. Capture Review Probability 기본값 0.2는 난이도 1·2에서 이전 난이도를 복습할 비율이다. 나머지 80%는 현재 난이도이며, 복습은 이전 난이도 중 균등 선택한다. 0이면 복습을 끈다. 세부 난이도 변경은 에피소드 경계에서만 반영한다. Inspector Fen은 사용자 Positions 배열을 그대로 사용하므로 자동 승급 본 학습에는 Pgn Training을 사용한다.

대국 기록에는 captureDifficulty(목표 난이도), sampledCaptureDifficulty(실제 복습 포함 샘플 난이도)가 포함된다. TensorBoard의 Curriculum/CaptureN/Success는 실제 샘플 난이도의 성공률이다. 별도 평가 결과의 TrainingSuccess와 Success를 비교하면 훈련 표본과 미사용 표본의 차이를 볼 수 있다.

재빌드 후 **새 run-id**로 실행한다. 이전 성공률 상태는 새 데이터·세부 난이도와 호환되지 않아 --resume할 수 없다. 원하면 --initialize-from=이전run으로 가중치만 이어서 시작한다. 기존 평가 16개는 Data/Curriculum/Legacy에 보관하며 새 훈련에 섞지 않는다.

## 전 단계 데이터 확장 및 오프닝 시작 (2026-10-01)

| 단계 | 학습 배치 | 별도 평가 배치 | 유형 |
| --- | ---: | ---: | --- |
| 0 포획 | 3,072 | 192 | 기존 세 난이도 유지 |
| 1 포획과 방어 | 3,072 | 192 | 안전한 이득 / 유리한 교환 / 좋은·나쁜 포획 선택, 각 1,024/64 |
| 2 메이트 | 2,048 | 128 | 메이트 인 1 / 인 2, 각 1,024/64 |
| 3 엔드게임 | 2,048 | 128 | KQK / KRK, 각 1,024/64 |
| 4 중반 | 5,120 | 256 | 다양한 실제 중반 |
| 5 전체 대국 | 1,025 | 129 | 3수·4수 오프닝 각 512/64 + 표준 초기 배치 1개 |

Inspector의 **Standard Start Probability** 기본값은 0.2다. 0이면 모두 오프닝, 1이면 모두 표준 초기 배치다. Pgn Training의 5단계에서만 적용하며, 기본적으로 3수 오프닝 40%·4수 오프닝 40%·표준 시작 20%가 된다. 3~4수는 백과 흑이 각각 둔 횟수다. 기보의 앞부분은 반복·캐슬링 이력을 복원하는 용도로만 재생하고, 포획 보상·에피소드 반수는 새 위치에서 시작한다. 기록의 curriculumCategory와 sourceStartPly로 시작 유형을 확인한다.

오프닝은 30기물 이상, 체크 아님, 기물 점수 차이 1 이하를 사용한다. 동일 ECO가 한 유형의 5%를 넘지 않도록 제한(정수 올림)하고, 앞 4반수가 같은 수순도 6.25% 이하로 제한했다. 엔진이 검증한 최선 오프닝이나 사람 수순 모방 학습은 아니다. 시작점을 넓혀 중반 경험을 늘리는 방식이며 표준 초기 배치 학습도 유지한다.

각 단계의 종료 조건·보상은 기존과 같다. 평가 표본은 1~5단계별 128개를 유형별로 고르게 선택해 양색 256회로 확대했다. 단계 5는 표준 시작 1개와 오프닝 127개를 평가한다. 유형별 성공률은 평가 JSON의 categories에 기록하고, 기존 단계 전체 성공률로 승급한다. 평가 시간이 늘어나는 만큼 평가 주기 조정은 config/chess_evaluation.yaml에서 할 수 있다.

새 데이터·설정을 적용하려면 Training 플레이어를 재빌드하고 새 run-id로 TrainChessSuccess.py를 실행한다. 기존 가중치는 --initialize-from으로 가져올 수 있지만 이전 평가 상태의 --resume은 사용하지 않는다.
