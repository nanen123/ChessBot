# ChessBot Curriculum

## 실제 PGN 학습 연결

현재 기본 Position Source는 **Pgn Training**이다. 단계마다 수집한 **train 64개** 중 무작위 선택하며 eval 16개는 런타임 리소스에 포함하지 않는다. 학습은 실제 경기의 지정 위치에서 Self-Play로 이어진다. 사람의 이후 수순을 정답으로 따라 하는 모방 학습은 아니다.

`Tools/BuildCurriculumDataset.py`가 `Data/Curriculum/*.train.pgn`을 검증하고 `Assets/Resources/ChessCurriculumTraining.json`으로 변환한다. 변환된 384개 항목을 이미 포함했으므로 처음에는 변환 명령 없이 Training 플레이어를 다시 빌드하면 된다. 실행 파일에는 필요한 데이터가 포함되며 인터넷·원본 PGN·Python chess 패키지 없이 실행된다.

현재 소스는 [실제 경기 자료 안내](../Data/Curriculum/README.md)의 선정 기준을 따른다. 아래 단계 표의 소수 수제 배치는 **Position Source = Inspector Fen**으로 선택하는 대체 데이터다. 단계별 종료 조건·보상·반수 한도는 두 소스에 공통 적용한다. Pgn Training에서는 Lessons의 Positions 배열을 사용하지 않으며 나머지 설정은 계속 Inspector에서 조절한다.

- 0~4단계: 해당 train 기보의 시작 수순까지 재생해 초기화하고 색을 번갈아 반전한다. 캐슬링·앙파상·50수 카운터·반복 이력을 보존한다.
- 기보 이전 수순의 포획에는 보상을 주지 않는다. 에피소드 반수·승리 보상 감소·반수 제한·관측 진행률은 선택한 위치에서 **0부터** 시작한다.
- 5단계: 표준 초기 배치에서 시작한다. 이 단계의 PGN은 출처 정보이며 원본 경기 수순을 강제로 진행하지 않는다.
- 잘못된 수순, FEN 불일치, 종료 배치, eval 데이터 또는 빈 단계는 오류로 중단한다. 수제 배치로 조용히 대체하지 않는다.
- JSONL 기록에는 datasetId, sourceGame, sourceStartPly, sourceMirrored, historyInitialFen, historyMoves가 추가된다. historyMoves 후 moves를 재생하면 반복 이력을 포함해 학습 대국을 복원할 수 있다.
- 데이터 확장 후 프로젝트 루트에서 `.venv-training/Scripts/python.exe Tools/BuildCurriculumDataset.py` 실행 → Unity 재빌드가 필요하다. 생성기 의존성은 데이터 안내를 따른다.

현재 YAML은 단계 0 고정값을 제공하며 성공률 기반 실행기가 승급을 제어한다. 0단계 첫 수 과제와 초기 단계 반복 벌점은 아래 규칙을 따른다. 새 실험은 `--run-id=pgn-curriculum-first`처럼 기존 결과와 다른 이름을 사용한다.

## 실행과 공통 원칙

`config/chess_sac.yaml`은 SAC Self-Play와 6단계 커리큘럼을 사용한다. 새 코드를 포함하도록 **Training 실행 파일을 다시 빌드**한 뒤 실행한다.

```powershell
conda activate mlagents
python Tools/TrainChessSuccess.py config/chess_sac.yaml --run-id=pgn-curriculum-first --env=output/chess-training/ChessTraining.exe --no-graphics --torch-device=cuda
```

단계 번호는 0~5다. Python의 `curriculum_stage` 값을 각 환경이 **새 에피소드 시작 시에만** 읽는다. 성공률 승급 실행기는 승급 시 전체 환경을 reset해 새 단계를 함께 적용하며 시작 포지션은 각각 무작위로 선택한다. 0~4단계는 각 환경에서 색을 번갈아 반전해 양쪽이 문제의 주인공 역할을 경험한다. 5단계는 항상 표준 초기 배치에서 백이 먼저 시작한다.

두 Agent가 같은 보드를 사용하고, 종료 시 양측 에피소드를 함께 종료한 뒤 다음 Academy 단계에서 보드를 한 번 초기화한다. 모든 단계에서 합법 수 Action Masking과 기존 특수 규칙을 유지한다. 이번 구현은 기존 모델과 같은 관측 844개·행동 8577개를 유지하며 단계 번호를 별도 관측으로 추가하지 않는다. 전체 반복 이력을 관측하지 않는 기존 한계에 더해 초기 과제의 목표도 직접 관측하지 않으므로 단계 간 학습 간섭 가능성이 있다.

## 단계 / 학습 내용 / 종료 조건 / 보상

아래의 '주인공'은 해당 시작 포지션에서 먼저 움직이는 색이다. 반대 색도 같은 정책으로 Self-Play하며 별도의 스크립트 상대를 사용하지 않는다.

| 단계 | 학습 내용과 시작 포지션 | 에피소드 종료 조건 | 보상 |
| --- | --- | --- | --- |
| 0. 첫 수 유리한 포획 | 실제 PGN의 12기물 이하 배치. 수제 대체 배치 3개도 제공 | 첫 합법 수 1 ply 직후 종료. 실제 체스 종료 우선 | 상대의 모든 한 수 응수 뒤에도 순기물 이득이 양수이고 즉시 메이트를 허용하지 않는 포획이면 공통 포획 보상과 +0.1. 그 외 -0.1이며 불리한 포획의 즉시 포획 보상은 억제. 상대에게 반대 부호 |
| 1. 포획과 방어 | 되잡힘이 가능한 배치, 불리한 교환과 유리한 교환이 포함된 3개 포지션 | 12 plies 또는 실제 체스 종료. 첫 포획 직후에는 끝내지 않아 응수·재포획을 경험 | 공통 포획 보상. 12 plies에서 주인공의 순포획 점수 >0이면 +0.1, <0이면 -0.1, =0이면 0. 상대에게 반대 부호 |
| 2. 메이트 인 1·2 | 킹+퀸의 메이트 인 1 및 강제 메이트 인 2 포지션 | 실제 승패·무승부 또는 3 plies. 메이트 인 1에 실패해도 남은 3 plies 범위 안에서 계속 진행 | 체크메이트는 공통 승패 보상만 적용. 3 plies까지 정상 종료 없이 메이트에 실패하면 주인공 -0.1, 상대 +0.1. 별도 성공 보너스 기본값은 0 |
| 3. 간단한 엔드게임 | 킹+퀸 대 킹, 킹+룩 대 킹 | 실제 체스 종료 또는 100 plies 중단 | 공통 포획·승패·정상 무승부 보상. 한도 중단에는 종료 보상 없음 |
| 4. 중반 대국 | 루이 로페즈 및 퀸즈 갬빗 계열의 합법적인 20-ply 수순을 재생한 2개 시작 FEN | 실제 체스 종료 또는 256 plies 중단 | 공통 보상. 한도 중단에는 종료 보상 없음 |
| 5. 전체 대국 | 표준 초기 배치 | 실제 체스 종료 또는 512 plies 중단 | 공통 보상. 한도 중단에는 종료 보상 없음 |

0~2단계의 문제 한도는 **과제 자체의 종료**이므로 `EndEpisode()`를 사용한다. 과제 성공/실패는 체스 승리/패배/무승부로 기록하지 않는다. 3~5단계 한도는 진행 중 대국의 시간 제한이므로 `EpisodeInterrupted()`를 사용한다. 어느 단계든 정상 체스 결과가 같은 수에 발생하면 과제 한도보다 우선하며 추가 과제 보상을 중복 적용하지 않는다.

Inspector Fen 모드의 중반 FEN에는 캐슬링 권리·차례·반수 카운터를 보존하지만 이전 반복 이력은 없다. 기본 Pgn Training 모드는 이전 수순의 반복 이력도 보존한다. 초기 데이터는 소규모 검증용 포지션 묶음이며, 광범위한 전술 데이터셋이나 실력 검증을 대신하지 않는다.

## 공통 보상

- 포획: `Capture Reward × 잡힌 기물 점수`, 상대에게 같은 크기의 음수. 기본 배율 0.05, 폰 1 / 나이트·비숍 3 / 룩 5 / 퀸 9. 되잡힘은 나중의 별도 포획으로 처리한다.
- 승리: `Win Reward + (Minimum Win Reward - Win Reward) × Clamp01(진행 plies / 감소 기준 plies)`. 기본 1에서 0.5로 감소한다.
- 패배: `-승리 보상 × Loss Reward Multiplier`, 기본 배율 1.
- 정상 무승부: 백 -0.2 / 흑 +0.2. 스테일메이트·반복·수순 규칙·기물 부족 등 실제 체스 무승부에만 적용한다.
- 커리큘럼 실패·중립 종료·학습 한도 중단을 정상 무승부로 간주하지 않는다.
- 포획 보상과 종료 보상은 누적된다. 일률적인 매 수 벌점, 체크 보너스, 승격 자체 보너스는 없다. 0~2단계에는 아래의 반복 벌점만 추가한다.

`Win Reward Decay Plies = 0`이면 **현재 에피소드의 단계별 반수 한도**를 감소 기준으로 사용한다. 모든 단계에서 동일한 시간 척도를 원하면 512 등으로 명시한다. 한쪽의 한 수가 1 ply이며 두 색이 각각 한 번 두면 2 plies다.

## Inspector에서 조절하기

`Chess Training Environment`의 Curriculum 섹션:

- **Use Curriculum**: 끄면 기존 표준 초기 배치와 Maximum Plies를 사용한다.
- **Position Source**: 기본 Pgn Training은 수집한 학습 기보를 사용한다. Inspector Fen은 아래 Positions 배열을 사용한다.
- **Preview Lesson**: Python이 `curriculum_stage`를 보내지 않을 때 사용할 단계(0~5). 에디터 무작위 미리보기에는 기존 Allow Heuristic Preview도 켜야 한다.
- **Lessons**: 반드시 6개. 각 항목의 Name, Ending, Maximum Plies, Success Reward, Failure Penalty, Positions(FEN 배열)를 조절한다. 배열 순서가 YAML의 0~5와 대응한다.
- **Ending = First Move Favorable Capture**: 항상 첫 수 1 ply에 종료한다. 이 모드에서는 Maximum Plies 값을 늘려도 종료 시점이 늘어나지 않는다.
- **Success Reward / Failure Penalty**: 0~2단계의 비체스 과제 종료에만 적용. Failure Penalty는 양수 크기를 입력한다. 실제 체스 종료에는 공통 종료 보상을 적용한다.

단계별 설정은 시작할 때 유효성 검사한다. 이미 종료된 포지션이나 차례가 아닌 쪽의 킹이 체크 상태인 FEN은 거부한다. 0~4단계의 입력 FEN은 기본적으로 문제를 풀 쪽이 먼저 움직이도록 작성한다. 매 단계의 최대 반수는 관측의 진행률 분모로도 사용한다. Inspector 변경은 Play 전 적용하며 실행 파일 학습에는 재빌드가 필요하다.

## 성공률 기반 단계 전환

2026-10-01부터 진행률 기반 승급을 제거했다. 자동 평가, 성공률·이전 단계 유지 기준, 재개 방법은 [006.AutomaticEvaluation.md](006.AutomaticEvaluation.md)를 따른다. 기본적으로 50,000 step마다 평가하고 최소 100,000 step 학습 후 연속 2회 통과해야 승급한다. 승급 순간에는 전체 환경을 reset하고 이전 과제 replay buffer를 비운다. 이에 승패 보상은 부여하지 않는다.

일반 mlagents-learn만 실행하면 단계 0에 머문다. 위의 TrainChessSuccess.py 실행 명령을 사용한다. 단계별 종료 조건과 보상은 이 문서의 표를 따른다.

## 반복 억제 및 첫 수 과제 개편 (2026-10-01)

Early Lesson Repetition 설정은 0~2단계에만 적용한다. 동일한 보드·차례·캐슬링 권리·합법 앙파상 상태의 두 번째 방문부터 움직인 Agent에게 기본 -0.005를 준다. 상대에게 보상을 옮겨 주지 않는다. 에피소드 시작 위치는 1회로 세며 PGN 이전 이력은 벌점 방문 횟수에 포함하지 않는다. 실제 무승부 판정의 PGN 이력은 계속 보존한다.

- Repetition Penalty: 0.005. 0이면 비활성화.
- Repetition Penalty From Occurrence: 2. 최소 2.
- Maximum Repetition Penalty Per Agent: 에피소드당 각 Agent 최대 0.05.
- 3~5단계, 커리큘럼 비활성 상태, 실제 체스 종료 수 및 무승부 청구에는 벌점을 주지 않는다.
- 반복 수 자체를 마스킹하지 않는다. 합법 수와 무승부 청구는 계속 선택할 수 있다.
- TensorBoard: Chess/RepeatedPositions, Chess/RepetitionPenalty. 첫 지표는 모든 단계의 에피소드 내 재방문 횟수다.

0단계의 유리한 포획은 잡은 기물 점수 + 승격 증가분에서 상대의 모든 합법 응수 중 최대 포획·승격 이득을 뺀 값이 양수인 경우다. 상대의 즉시 체크메이트가 하나라도 있으면 실패다. 최선의 장기 전술을 증명하는 기준은 아니다. 첫 수로 끝나는 과제에서 나쁜 희생의 포획 보상이 실패 벌점을 상쇄하지 않도록, 이 과제의 불리한 포획에는 즉시 포획 보상을 주지 않는다. 1~5단계 포획 보상은 유지한다.

기존 프리팹의 Capture Reward 0.1, 백/흑 무승부 0 설정은 보존했다. 위 공통 보상 수치는 코드 기본값이며 실제 학습은 Inspector 값을 사용한다. 새 학습에는 Training 실행 파일을 재빌드하고 새 run-id를 사용한다. 변경된 데이터와 평가 설정으로 이전 성공률 상태를 --resume 할 수 없다. 기존 가중치는 새 run에 --initialize-from=이전run으로 사용할 수 있다.
